# TASK: Replace WhaleCall's typography and copy system with a professional, Uber-style one

The app currently reads as AI-generated. Two things cause it, and both must go:

1. **The letterspaced uppercase monospace "eyebrow" label above every section** — `WHALE CALL OPERATING AREA`, `COASTWATCH DISPATCH`, `WHERE WE LAUNCH`, `NEW CROSSING`, `PASSAGE DETAILS`, `RIGHT NOW`, `OFF THE CHART`, `ISLAND #1`. This one pattern is the single biggest tell. It appears on nearly every screen.
2. **Whimsical, over-written product copy** — "Voyage mode", "Response mode", "Pick your waterline", "Not an app. A local hand.", "Seven fictional islands. One good idea.", "A small squall.", "Keep calm. We know this water."

Target: **a real transportation product.** Think Uber, Lyft, Bolt — plain functional language, one clean sans-serif, high contrast, generous whitespace, no decorative flourishes. Nothing should sound like it's narrating an adventure.

**Do not change the landing page title "Adaptive Maritime Dispatch."** That stays exactly as-is. Everything else in this document is in scope.

---

## 1. Typography — replace the whole system

### Remove
- **The display serif** used for every headline ("Get there by water.", "The live fleet.", "Keep calm. We know this water."). Delete the font import and every rule that applies it. A high-contrast decorative serif on a dispatch app is the wrong register entirely.
- **The monospace eyebrow font** and, critically, the `text-transform: uppercase` + wide `letter-spacing` treatment applied with it. Search the codebase for `letter-spacing` values above `0.1em` and for any shared `.eyebrow` / `.kicker` / `.label` / `.overline` class and remove them.

### Replace with one family
Use **Inter** (or the system stack `-apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, Helvetica, Arial, sans-serif`). One family for everything — headings, body, labels, buttons. Load weights 400 / 500 / 600 / 700 only.

### Type scale (use these exact values)

| Role | Size / Weight | Notes |
|---|---|---|
| Page title (h1) | 40px / 700, line-height 1.15, letter-spacing −0.02em | 32px on mobile |
| Section heading (h2) | 28px / 600, letter-spacing −0.01em | |
| Card / subsection (h3) | 20px / 600 | |
| Body | 16px / 400, line-height 1.55 | Never below 15px for real content |
| Secondary text | 14px / 400, muted gray | |
| Form label | 14px / 500, **sentence case, no letter-spacing** | |
| Button | 16px / 600 | |
| Stat number | 32px / 700, tabular-nums | |

**Hard rules:**
- Negative letter-spacing on large headings, `0` everywhere else. **No positive letter-spacing anywhere in the app.**
- **Sentence case everywhere.** The only uppercase permitted is a live status chip (`ARRIVING`, `EN ROUTE`) — and even those become sentence case: `Arriving`, `En route`, `Available`, `Offline`.
- No italics, no small-caps, no decorative dividers, no `·` interpuncts strung between phrases.

## 2. Delete the eyebrow pattern entirely

Every kicker label above a heading gets **deleted, not reworded.** If the heading below it can't stand alone, rewrite the heading — don't reintroduce a label.

Delete all of these on sight:

`WHALE CALL OPERATING AREA` · `WHALE CALL · LOCAL PASSAGE, DONE RIGHT` · `WHALE CALL CHART` · `WHALE CALL OFFICE` · `COASTWATCH DISPATCH` · `WHERE WE LAUNCH` · `NEW CROSSING` · `PASSAGE DETAILS` · `NAVIGATE` · `RIGHT NOW` · `OFF THE CHART` · `WHEN THE ORDINARY IS NOT ENOUGH` · `STAYING ON CHANNEL · ALL BOATS ACCOUNTED FOR` · `ISLAND #1`–`#7` · `VOYAGE MODE` · `RESPONSE MODE` · `CROSSING TRIP-XXXX`

The two mode pills in the header (`VOYAGE MODE` / `RESPONSE MODE`) are removed completely — see §3.

---

## 3. Kill the "modes"

"Voyage mode" and "Response mode" are the most fictional-sounding thing in the product. Uber doesn't have modes; it has a ride screen and an emergency button.

- **Remove both header pills.** They communicate nothing a user needs.
- **"Voyage mode" → just the default app.** No label at all.
- **"Response mode" → "Emergency".** Everywhere: page heading, buttons, links, the floating action button, the footer link.
- The emergency page keeps its **dark, red-accented treatment** — that's genuinely good UX for an emergency screen and should stay. Only the *language* changes.

## 5. Visual system — match a real transportation app

**Color.** Cut the palette down hard. The cream/sand/teal/coral mix currently reads decorative.
- Background: white `#FFFFFF`; secondary surfaces `#F6F6F6`
- Text: primary `#000000`, secondary `#6B6B6B`, tertiary `#9A9A9A`
- Borders: `#E5E5E5`
- Primary action: **black `#000000` with white text** (this single change does more than anything else to make it look like Uber)
- Emergency accent: `#D93025` — used only on the emergency screen and the emergency button
- Optional brand accent: keep one teal `#0E7C7B` for links and the logo mark **only** — not for buttons, not for backgrounds
- Delete the cream `#F5E6C8` page backgrounds and the large teal section blocks entirely

**Buttons.** 48px tall, 8px radius (not fully-rounded pills — the current pill shape reads playful), 600 weight, 16px. Primary = black fill. Secondary = white fill with a `#E5E5E5` border. Destructive/emergency = `#D93025` fill.

**Cards.** White, 12px radius, `1px solid #E5E5E5`, no drop shadows (or a single very subtle one). Remove the decorative pastel circles currently sitting in the corners of the island cards.

**Layout.**
- Max content width 1120px, centered, 24px side padding.
- **Fix the dead space.** The `/emergency` and `/book` pages currently leave roughly the bottom half of a desktop screen empty. Vertically center the card in the available viewport, or introduce a two-column layout (map left, form right) that fills the space.
- Section spacing: 64px desktop / 40px mobile. Consistent 8px spacing scale throughout (8/16/24/32/48/64).
- **Replace the decorative island illustrations** on `/book` and `/fleet` with a clean, functional map: flat shapes, thin `#E5E5E5` grid, black dots for docks, a black line for the route. Remove the tan blob boats — a small directional triangle or boat glyph, sized proportionally to the islands, not the current oversized teal ellipse that covers half the departure island.
- **Differentiate boat classes visually** on `/fleet` — all 72 cards currently show an identical tan ellipse whether it's a rescue boat, a catamaran, or a speedboat.

**Status chips.** Small, 12px, 500 weight, sentence case, subtle background: Available (green), En route (amber), On trip (blue), Offline (gray). No uppercase, no letter-spacing.

## 6. Voice rules for any new copy

Write like product UI, not like a novel:
- **Say what the thing does.** "Book a ride", not "Plan a crossing."
- **Second person, present tense, active voice.** "Choose your destination."
- **No metaphors.** Nothing about tides, wakes, shoals, squalls, channels, or the horizon.
- **No two-sentence poetic fragments.** "Not an app. A local hand." is exactly the pattern to eliminate.
- **No self-congratulation.** Don't tell the user the service is warm, local, or better — show the fare and the ETA.
- **Never call the islands "fictional"** in the UI. It breaks the product illusion instantly for a judge.
- **Numbers over adjectives.** "54 boats available" beats "boats ready to launch."
- Sentence case for every heading, label, and button.

## 7. Fix these real defects while you're in the files

Verified issues on the live site — fix them as part of this pass:

1. **Show real API errors.** The client renders "Dispatch could not be reached. Try again." and "We could not reach the dock. Please try again." for responses that *did* arrive. The API returns useful messages (`"No rescue boat is currently available."`, `"No boats are available in that class right now."`) — render `response.error` and reserve a generic message for actual network exceptions.
2. **Map slugs to names.** The trip page prints `coral-cove` / `mango-harbor` instead of "Coral Cove" / "Mango Harbor".
3. **Fix the header link.** "Book a crossing" → `/book`.
4. **Never block a submit silently.** Selecting the same island for pickup and destination lets you proceed to a Continue button that does nothing with no message. Filter the departure island out of the destination list, and always render a reason when a submit is blocked.
5. **Remove `maximum-scale=1`** from the viewport meta tag — it blocks pinch-zoom (WCAG 2.1 AA failure).
6. **Tap targets.** "Use my location" and "Cancel" on the emergency screen are 16px tall; nav links are 36px. Minimum 44px for every interactive element.
